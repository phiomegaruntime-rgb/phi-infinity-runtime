# PHI-INFINITY AMENDMENT 06
# MECHANICAL PROPOSITION SEMANTICS

**Status:** AUTHORITATIVE NON-GENERATIVE SUCCESSOR AMENDMENT

THIS AMENDMENT ADDS NO NEW FUNDAMENTAL CAUSAL OPERATION.

THIS AMENDMENT DEFINES HOW ALREADY-FROZEN MECHANICAL CONCEPTS MAY BE
REPRESENTED AS TYPED PROPOSITIONS.

IT DOES NOT DEFINE HOW THOSE PROPOSITIONS ARE DERIVED.

It does not modify the frozen Mother Mechanics, the Fundamental Laws,
Amendments 01–05, temporal closure, native represented mechanics, or raw
bootstrap behavior.

## 1. Type and constructor separation

\[
\boxed{\text{PROPOSITION TYPE}\neq\text{PROPOSITION CONSTRUCTOR}}
\]

\[
\boxed{\text{TYPE EXISTS}\neq\text{INSTANCE EXISTS}}
\]

\[
\boxed{\text{UNINHABITED TYPE}\neq\text{FALSE PROPOSITION}}
\]

A proposition type may exist with zero authorized raw constructors and zero
authorized derived constructors. Type declarations are semantic substrate only;
they do not create receipts or `DERIVED_M` facts.

## 2. Initial proposition vocabulary

This amendment freezes only the minimum vocabulary required to close the
Phase 24 type frontier:

- `REAL_DIFFERENCE_EXISTS`;
- `REAL_CONSEQUENCE_EXISTS`;
- `MECHANICAL_EXISTENCE_PROVED`;
- `MECHANICAL_WITNESS_CONSTRUCTED`.

This amendment does not define proposition types for Dependency, Exchange,
Transformation, Propagation, or Continuation.

## 3. Scope-bound real difference

`REAL_DIFFERENCE_EXISTS` means only:

> A mechanically real difference exists within the exact mechanical scope
> authorized by its receipt genealogy.

It is a scope-bound proposition, not a universal standalone difference object.
It does not imply basis-local discrimination, numerical inequality, pairwise
endpoints, magnitude, direction, metric, distance, causation, dependency,
exchange, transformation, consequence identity, or any constructor.

No universal endpoint schema is required. A proposition type does not define
how a `REAL_DIFFERENCE_EXISTS` instance is obtained.

## 4. Witness-free consequence existence

`REAL_CONSEQUENCE_EXISTS` means only:

> For a qualified mechanical premise and exact inherited scope, frozen
> mechanical authority requires existence of at least one real consequence.

It does not specify consequence identity, number, magnitude, direction,
location, timing, exchange, transformation, propagation, continuation, or a
concrete witness.

`REAL_CONSEQUENCE_EXISTS` is existential and witness-free.

## 5. Existence and witness status

\[
\boxed{
\texttt{MECHANICAL\_EXISTENCE\_PROVED}
\neq
\texttt{MECHANICAL\_WITNESS\_CONSTRUCTED}
}
\]

`MECHANICAL_EXISTENCE_PROVED` means that existence is mechanically proven but
no concrete witness is identified.

`MECHANICAL_WITNESS_CONSTRUCTED` means that a separately authorized rule
identifies an exact mechanical witness.

This amendment provides no witness-construction rule.

## 6. No Skolemization

From `REAL_CONSEQUENCE_EXISTS`, the system must not generate
`consequence_1`, `consequence_unknown`, `hidden_consequence`, an opaque node,
or any equivalent placeholder.

An existential proposition remains witness-free until a separate authorized
witness-construction rule exists.

## 7. Immutable proposition record

An authorized proposition record contains only:

- proposition identity;
- predicate type;
- exact mechanical scope;
- subject receipt IDs;
- proposition status;
- witness status;
- parent receipt IDs;
- proof genealogies.

The record is immutable. It contains no arbitrary payload, semantic label,
candidate object, generated witness, score, metric, or hidden mechanism.

## 8. Frozen proposition-type registry

The proposition-type registry is separate from `FrozenRuleRegistry`.

It defines only type identity, exact semantic statement, allowed scope schema,
existential status, witness-bearing status, constructor policy, authority
source/range/hash, and semantic specification/hash.

It does not define premise-to-conclusion inference.

Constructor policies are:

- `NO_CONSTRUCTOR_CURRENTLY_AUTHORIZED`;
- `MECHANICAL_RULE_ONLY`;
- `FALSIFICATION_RULE_ONLY`;
- `NATIVE_REPRESENTED_SCOPE_ONLY`.

Caller-supplied mechanical facts are never authorized. Human and external
declarations remain access representation.

## 9. Scope and identity

Proposition identity depends only on frozen typed semantics and exact
scope/subjects. Scope may include access snapshot, mechanical configuration,
field/context, scale, genealogy, and mechanical execution lineage when
justified by the proposition.

There is no silent globalization, cross-access identity, cross-basis identity,
fuzzy equality, or semantic-similarity merge.

If two proof paths yield one exact proposition under one exact scope, preserve
one proposition identity and all proof genealogies.

## 10. Proof-kernel integration and raw firewall

Amendment 06 integrates with the Amendment 05 Proof Kernel only to validate
types, scope, identity, genealogy, witness status, and constructor policy.

The kernel must not create `REAL_DIFFERENCE_EXISTS` from Amendment 04, create
`REAL_CONSEQUENCE_EXISTS` without a registered mechanical rule, or create a
witness from an existential proposition.

Mechanical type declarations are `NON_GENERATIVE_SEMANTIC_SUBSTRATE`, not
`DERIVED_M`.

The raw path remains:

```text
AccessPackage
→ Amendment 03
→ Amendment 04
→ Amendment 05 Proof Kernel
→ no raw REAL_DIFFERENCE constructor
→ UNRESOLVED
→ FIRST_MECHANICAL_INFERENCE_RULE_FRONTIER
```

Amendment 06 is not a raw-bootstrap solution.
